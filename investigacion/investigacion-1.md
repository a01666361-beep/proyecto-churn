## Fase 1 · Lecturas y fichas

| Lectura | Lector(es) | Qué tomamos para el tablero |
|---|---|---|
| **A.** Nielsen, *10 Usability Heuristics for User Interface Design* | Gerardo Córdova | Visibilidad del sistema (1), control y libertad (3), consistencia (4), reconocer antes que recordar (6), diseño minimalista (8) y ayuda y documentación (10). También la escala de severidad de 0 a 4. |
| **B.** Rodden, Hutchinson y Fu, *Measuring the User Experience on a Large Scale* (HEART) | Irais Granados, Adán Ávila | El proceso *Goals → Signals → Metrics*: una meta se traduce en una señal y luego en un número rastreable. A veces es más fácil medir el fracaso (el abandono) que el éxito. |
| **C.** Estándar normativo y accesibilidad (WCAG del W3C) | Erick Silva | Contraste suficiente, no usar solo el color para comunicar, etiquetas visibles y usar títulos, espacios y jerarquía para organizar el contenido. |
| **D.** Frost, *Atomic Design* | Arlen Martínez, Víctor García | Átomos → moléculas → organismos → plantillas → páginas. Cada elemento debe tener un propósito, la página necesita un esqueleto que coloque primero lo importante, y tamaños y colores deben estar homologados. |

## Fase 2 · Contrato de diseño (reglas acordadas por el equipo)

1. La interfaz debe ser fácil de entender y usar, con elementos claros y organizados de forma lógica, para que el usuario pueda realizar tareas sin instrucciones.
2. Cada error se identifica con su rating de severidad (0 a 4) y se soluciona según su importancia.
3. La satisfacción del usuario se mide, no se asume (HEART, *Happiness*).
4. Todo abandono antes de confirmar se registra como señal de fracaso.
5. Adaptar el diseño a diferentes tamaños de pantalla.
6. Utilizar jerarquías para organizar el contenido.
7. Los elementos no solo deben ser visualmente atractivos, sino tener un propósito, origen y funcionalidad.
8. Respetar la coherencia en toda la página, con mismos tamaños, colores y todo homologado.
